# Security policy

## Report a vulnerability privately

Use [GitHub private vulnerability reporting](https://github.com/Xenox-developer/invariant/security/advisories/new).
Private reporting is enabled for this repository. Do not put exploitable details,
credentials, private archives or proprietary project data in a public issue.

Include affected INVARIANT/Codex/Docker versions, host platform, a minimal
reproduction, the expected trust boundary and the observed result. A sanitized
`invariant doctor --json` report helps. Coordinate any public disclosure through
the private advisory. No response-time SLA or bounty is promised.

## Supported versions

Security fixes target the latest 0.3.x release. Earlier source milestones are
historical and should be upgraded after backing up state. Rust libraries remain
versioned separately; fixes to supported source are documented in the changelog.

## Scope and boundaries

Storage layout 2 runs the coordinator, Codex runtime, reviewer and task execution
inside Docker. Only the trusted manager mounts the Docker socket. Agent and
executor containers have no host home, device passthrough, privileged mode,
published control port or arbitrary host filesystem mount. Optional quotas and
workload deadlines are disabled by default; this does not disable storage boundaries.

The host launcher streams project inputs into Docker volumes and writes only
exported artifacts/logs, a credential-free registry, and reviewed source changes.
An existing ChatGPT auth file may be copied once into Docker. Token refresh and
subsequent sign-in state remain there. Original personal Codex settings are not removed.

Native agent tasks/results can reach the provider. New persistent environments
enable command internet access by default; saved offline policies and the legacy
profile remain unchanged. Internet mode permits reachable
local-network services as well as the public internet. Workloads are administrator
inside their Linux environment. Original project writes occur only through guarded, reviewed delivery. This is not a multi-tenant isolation or
adversarial-evaluator attestation claim.

Reports omit private content by default, but user-selected IDs/metric names remain
user input. Explicit logs/diff/task exports and private backups can contain secrets.
Backups are unencrypted local files; native homes and host authentication are omitted.
Known secret-file values are redacted in captured logs, not every possible encoding
or secret generated by arbitrary code. Review files before sharing them.

See [runtime architecture](docs/ENVIRONMENT_ARCHITECTURE.md),
[experiment boundaries](docs/experiments/README.md) and
[release limitations](docs/experiments/ACCEPTANCE.md) for exact guarantees.
