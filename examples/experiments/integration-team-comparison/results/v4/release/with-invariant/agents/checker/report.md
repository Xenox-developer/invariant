# Точность численного интегрирования

Это малый детерминированный численный эксперимент: интегрируются x² и x⁴ на [0,1] при n = 10, 20, 40, 80 равных подынтервалах. Точные эталоны — 1/3 и 1/5; случайные данные и внешние библиотеки не используются.

Составной метод трапеций (trapezoid) использует половинные веса концов и единичные веса внутренних узлов. Составной метод Симпсона (simpson) при чётном n использует веса 1, 4, 2, …, 4, 1 с множителем h/3, где h = 1/n.

Независимая проверка всех 16 строк выполнена рациональной арифметикой Fraction: точные взвешенные суммы сопоставлены с интегралами и формулами ошибки Q−I. Для трапеций они равны h²/6 для x² и h²/3−h⁴/30 для x⁴. Для Симпсона получаются 0 для x² и 2h⁴/15 для x⁴. Все ненулевые теоретические ошибки положительны. Обе полученные реализации также импортированы и исполнены через integrate; каждое значение воспроизведено без изменения входных файлов.

Измеренные отношения E(n)/E(2n), вычисленные непосредственно из полученных ошибок:

| Метод и функция | 10→20 | 20→40 | 40→80 |
|---|---:|---:|---:|
| trapezoid_x2 | 4.0000000000 | 4.0000000000 | 4.0000000000 |
| trapezoid_x4 | 3.9969992498 | 3.9992499531 | 3.9998124971 |
| simpson_x4 | 15.9999999999 | 15.9999999893 | 15.9999999147 |

Отношения около 4 подтверждают второй порядок трапеций; отношения около 16 подтверждают четвёртый порядок Симпсона для x⁴. Небольшое отличие отношений для трапеций x⁴ от 4 объясняет член −h⁴/30. Эти выводы относятся к выбранным полиномам и сеткам, а не являются статистической оценкой.

Симпсон интегрирует x² точно в рациональной арифметике. В полученных данных ошибка относительно машинного представления 1/3 равна 5.5511151231257827e-17. Это округление двоичных чисел, а не ошибка дискретизации. Проверка использует допуск восьми ulp эталона и отдельно сравнивает оценку с рациональным интегралом; сам эталон 1/3 тоже не представим точно в float.

На графике errors.svg показаны три ряда с логарифмической шкалой абсолютной ошибки и линейной шкалой n. Почти нулевой ряд simpson x² исключён, поскольку характеризует округление, а не сходимость; логарифм нуля нигде не вычисляется.

comparison.csv сохраняет все исходные числовые значения. verification.json содержит SHA256 фактических байтов входных result.json, отношения ошибок и подробности рациональной проверки. Воспроизведение: `python3 -B build_report.py --inputs inputs --output OUTPUT_DIR`.
