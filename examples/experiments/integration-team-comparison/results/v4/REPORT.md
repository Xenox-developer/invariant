# Результаты исправления архитектуры INVARIANT

Реализованы передача результатов внутри Docker, постоянное клиентское соединение,
единая подготовка выгрузки, переиспользование проверенных файлов выгрузки,
курсор журналов, компактное наблюдение, перекрытие предварительной проверки с
подключением агента, завершение задачи по принятой квитанции и публикация снимка
без дополнительного копирования. Сохранены отдельный исполнитель, независимый
evaluator, полное окружение для продолжения и существующие проверки применения.

## Согласованность сравнения

Модель gpt-6.1-sol, усилие medium, Codex 0.163.0, вычислительный образ и флаги
инструментов совпадают. SHA-256 прежней suite сохранён: 5f3b4aa18a46fb44de7bc1e8acbc0132214025d6c1c974c91be2c787406f1e76.
В обоих вариантах используется тот же контракт исследования: два независимых
расчётных агента параллельно, затем отдельный проверяющий. Согласованные указания
по группировке действий переданы обоим вариантам. INVARIANT использует новый
режим завершения по квитанции; прямой — обычный Codex CLI. Прямой адаптер
baseline_v3.py не импортирует INVARIANT.

Порядок: first — INVARIANT → CLI; warm1 — CLI → INVARIANT;
warm2 — INVARIANT → CLI; warm3 — CLI → INVARIANT; release — INVARIANT → CLI. Каждая попытка получает новый
чат и рабочую папку. Общий исполняемый runtime и метаданные переиспользуются;
истории агентов между измеренными попытками не объединяются.

Все десять запусков прошли **85/85** неизменённых проверок. Реальные окна
ответов двух расчётных агентов пересекаются, а проверяющий стартует после них.
Численные оценки совпадают между вариантами с точностью лучше 1e-12.
Каждый генератор дополнительно принял правильные данные и отверг намеренно
искажённую оценку; этот контроль не использовал модель.

## Что подтверждено реализацией и логами

- Проверяющий получает два digest-bound результата, замороженных непосредственно
  в Docker. Промежуточная папка inputs на компьютере не создаётся. Выгрузка
  выполняется после всех этапов; полная история остаётся в Docker.
- Принятая квитанция переиспользована для каждой native-попытки. Полная приёмка
  не выполняется второй раз после успешного invariant_validate. Серверный статус
  interrupted сохраняется как фактический; успешность задачи определяется
  независимой квитанцией. Итоговые счётчики сверены с каждым ответом провайдера.
- Одинаковая предварительная проверка методов переиспользуется по точному
  замороженному состоянию. Изменение входов проверяющего создаёт новую проверку.
- Для ресурсоограниченных запусков перекрытие отключено: подготовка не расширяет
  заданный бюджет. До готовности baseline платный ход запрещён.
- Проверка исходной рабочей папки остаётся полной по manifest/hash, но не создаёт
  дополнительную копию. Публикация переносит тот же immutable snapshot, без
  разделяемых writable/hardlink деревьев; существующий GC остаётся применим.

Перед контрольной парой исправлены два обнаруженных регрессионными тестами
краевых случая: закрытие уже оборванного канала и квота на виртуальные родительские
директории. Они не меняют рабочий протокол исследования. Исходные версии каждой
пары зафиксированы отдельно в protocol.json; контроль проверяет код после этих двух исправлений. После серии дополнительно
сериализована публикация файлов на компьютере: два одновременно работающих
клиента получают одну выгрузку. Это изменение проверено двумя независимыми
процессами без модельных запросов; модельный исполнитель и протокол проверки
не менялись. Полный набор проекта прошёл 436 тестов, включая эти случаи.

## Продолжение и хранение

Управляющий контейнер аварийно остановлен через SIGKILL и запущен заново;
контекст восстановлен по прежнему run_ref. Повторная отправка завершённого
исследования и execute не создали новой попытки или обращения к модели.
Повторные status/collect не изменили задачи и не создали дубли результатов.
Неизменённый исходный проект повторно не импортировался.

Две реальные продолженные задачи прошли по **35** унаследованных проверок:
первая создала .venv и установила six==1.17.0, а также записала маркер вне workspace;
после нового перезапуска вторая использовала ту же .venv **без переустановки** и
прочитала маркер из сохранённого rootfs. Дополнительный проверяющий скрипт
зафиксирован по SHA-256 до запуска продолжения и независимо исполнил сохранённый
интерпретатор из точного checkpoint с рабочей папкой только для чтения;
версии пакета, sys.prefix, маркер и содержимое six.py подтверждены отдельно от
утверждений агента. sys.prefix остался /workspace/.venv.
solution.py и result.json сохранились побайтово. Повторные ключи возвращают
прежние исследования без нового вызова модели. .venv не попала в host-выгрузку.
Проверки продолжения и их стоимость исключены из исследовательских пар и
приведены отдельно в continuation.json.

Аудит хранения: verified=true, issues=[]. У агентов нет подключений домашней
папки компьютера, его устройств или Docker-сокета. Состояние и установки остаются
в Docker. На компьютере остаются исходники, результаты, логи и реестр.

## Стоимость и пределы вывода

Standard-кредиты — расчётный эквивалент по замороженным ставкам предыдущего
сравнения: за миллион некешированных входных / кешированных входных / выходных
токенов 50 / 2,5 / 250. Источник: [Codex pricing](https://developers.openai.com/codex/pricing/#token-rates).
Кешированные токены — часть входа, reasoning — часть выхода. Фактическая денежная
стоимость подписки для отдельных вызовов неизвестна. Расход внешнего чата,
разработка, smoke и продолжение не включены в таблицы исследовательских пар.

Попадания в кеш и скорость генерации провайдера вариативны. Часть улучшения
связана с меньшим числом обращений благодаря новому завершению и группировке
действий. Сохранившиеся снимки/evaluator и раздельный исполнитель имеют стоимость,
которой нет у прямого CLI: baseline сохраняет тома, но не обеспечивает эквивалентные
защищённые квитанции и полные rootfs checkpoints для каждого результата.

Основные доказательства: protocol.json, measurements.json,
checker-negative-control.json, continuation.json, storage-audit.json, unit-tests.log,
concurrent-collection.json, diagnostics/saved-observation-profile.json, deployment-audit.json.
Исходные результаты и журналы — в first/, warm1/, warm2/, warm3/, release/; прошлые v3
доказательства не пересоздавались.
